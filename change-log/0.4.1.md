## [0.4.1] - 2026-09-11

### 修复

- **[严重] 小程序侧无法按包名 / 目录短路径引入**：ESM 产物名为 `dist/index.esm.js`，而微信开发者工具"构建 npm"后只写包名时默认寻找 `<包名>/index.js`，相对路径引入也只会按 `路径` → `路径.js` → `路径/index.js` 三步解析。现 ESM 产物更名为 `dist/index.js`（CJS 仍为 `dist/index.cjs.js`），两种引入方式同时恢复
- **[严重] 类型声明为多文件树、存在悬空引用**：`tsc` 逐文件 emit 出 14 个 `.d.ts`，靠相对 `import` 串联，且 `dist/core/*.d.ts` 引用过 `../types/ble`（该文件当时未生成，0.4.0 用 `copyTypesPlugin` 打补丁）。现改为单文件声明，整棵类型依赖树被内联，不再需要该补丁
- 公共类型无法从包根导入：`src/index.ts` 从未再导出 `./types/ble`，消费者写不出 `const cfg: BLEHandlerConfig = {...}`，只能依赖类型推断。现补 `export type * from "./types/ble"`

### 变更

**构建产物形态**

- `rollup.config.mjs` 改为导出配置**数组**：第 1 项产出运行时代码（`dist/index.cjs.js` + `dist/index.js`），第 2 项独立跑一趟 `rollup-plugin-dts` 合并出单文件 `dist/index.d.ts`
- 删除内联 `copyTypesPlugin`（及 `fs` / `path` 导入），多文件时代的整套类型补丁随之作废
- `tsconfig.json`：`declaration` 置为 `false` 并删除 `declarationDir`，`rollup-plugin-typescript2` 不再逐文件 emit `.d.ts`
- `build` 脚本改为 `npx rimraf dist && rollup -c`，防止旧的多文件 `.d.ts` 残留被打进发布包
- 新增 devDependency `rollup-plugin-dts@^6.5.1`

**微信小程序接入约定**

- `package.json` 新增 `"miniprogram": "dist"`（「构建 npm」实际读取的字段）；`module` 与 `exports.import` 由 `./dist/index.esm.js` 改为 `./dist/index.js`
- `exports["."]` 补上 `"types": "./dist/index.d.ts"` 条件，修复 `node16` / `bundler` 模块解析下找不到声明文件
- `main` 保持 `dist/index.cjs.js`，Node 侧 `require` 不会拿到 ESM；小程序侧走 `miniprogram` 字段，互不干扰
- README 安装章节补充「构建 npm」步骤与三条注意事项：必须 `npm i` 而非 `-D`（工具只扫 `dependencies`）、入口必须是 `index.js`、`exports` / `module` 在构建 npm 阶段不被识别

### 发布产物

- 文件数 **18 → 5**，体积 25.0 kB → 24.7 kB
- `dist/` 仅保留 `index.js`（ESM）、`index.cjs.js`（CJS）、`index.d.ts`（单文件声明）

- `npm run build` + `tsc --noEmit` 通过
- `dist/index.d.ts` 单文件约 27.4 kB，零相对 `import` 残留
- 以消费者视角遍历导入全部 8 个公共类型，`tsc --strict` 零报错；运行时导出逐字节未变
- `npm pack --dry-run` 确认发布清单无 `index.esm.js` 残留
